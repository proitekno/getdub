# getdub

Быстрый поиск дубликатов файлов с персистентным индексом на SQLite.

# 📖 Руководство пользователя getdub

**getdub** — это сверхбыстрая утилита командной строки для поиска дубликатов файлов с использованием персистентной базы данных (SQLite). Она умеет индексировать диски, вычислять криптографические хеши и находить точные копии файлов, поддерживая инкрементальное обновление через USN Journal (для NTFS).

## ⚠️ Важные требования
1. **Запуск от имени Администратора:** Настоятельно рекомендуется запускать `getdub` из PowerShell/CMD с правами администратора. Это необходимо для доступа к USN Journal и прямому чтению MFT (что значительно ускоряет работу).
2. **База данных:** По умолчанию БД хранится в папке `.\fdb\getdub.fdb` (в директории запуска) или в `%LOCALAPPDATA%\getdub\getdub.fdb`.

---

## 🚀 Быстрый старт

Самый частый сценарий: просканировать диск, вычислить хеши и найти дубликаты.

```powershell
# 1. Сканируем диск D: с вычислением хешей
getdub.exe idx drive D --hash

# 2. Смотрим найденные группы дубликатов
getdub.exe fdb query --duplicates
```

---

## 🛠️ Справочник команд

### 1. Индексация (`idx`)
Сканирует файловую систему и сохраняет метаданные в БД.

```powershell
getdub.exe idx drive <БУКВА_ДИСКА> [ОПЦИИ]
```
**Опции:**
* `--all` : Сканировать все локальные фиксированные диски.
* `--incremental` : Выполнить быстрое инкрементальное сканирование, читая только изменения из USN Journal (работает только на NTFS, если журнал активен).
* `--hash` : Сразу после сканирования вычислить частичные (xxh3) и полные (BLAKE3) хеши файлов. **Обязательно для поиска дубликатов.**
* `--include "*.mp3,*.flac"` : Сканировать только файлы, соответствующие маске (через запятую).
* `--exclude "*.tmp,*.log"` : Игнорировать файлы, соответствующие маске.

**Примеры:**
```powershell
# Сканировать только музыку с хешированием
getdub.exe idx drive E --include "*.mp3,*.flac,*.wav" --hash

# Быстрое обновление индекса диска C: (проверяет только измененные файлы)
getdub.exe idx drive C --incremental
```

### 2. Работа с базой данных (`fdb`)
Управление накопленными данными и запросы.

* **Статистика:**
  ```powershell
  getdub.exe fdb stats
  ```
  *Показывает размер БД, количество томов, проиндексированных файлов, хешированных файлов и игнорируемых записей.*

* **Поиск дубликатов:**
  ```powershell
  getdub.exe fdb query --duplicates [--limit 50]
  ```
  *Ищет файлы с одинаковым **полным хешем** (100% совпадение). `--limit` ограничивает количество выводимых групп.*

* **Поиск кандидатов:**
  ```powershell
  getdub.exe fdb query --candidates [--limit 50]
  ```
  *Ищет файлы с одинаковым размером и **частичным хешем** (первые 4 КБ). Полезно для быстрой прикидки перед полным хешированием.*

* **Экспорт в CSV:**
  ```powershell
  getdub.exe fdb export --out report.csv
  ```
  *Выгружает все проиндексированные файлы в таблицу для анализа в Excel.*

* **Мягкое удаление тома (Soft Delete):**
  ```powershell
  getdub.exe fdb erase --volume "D:\"
  ```
  *Помечает все файлы указанного тома как удаленные (`is_deleted = 1`), не стирая их из БД физически. Полезно, если диск был отключен или переформатирован.*

### 3. Проверка состояния USN (`usn`)
Позволяет узнать, будет ли работать инкрементальное сканирование на конкретном диске.

```powershell
getdub.exe usn status --volume C:\
```
*Выведет `ACTIVE` и текущий USN, либо `NOT ACTIVE` (в этом случае `--incremental` автоматически откатится к полному сканированию).*

### 4. Верификация (`verify`)
Встроенный механизм самопроверки (используется в автотестах, но полезен и вручную).

```powershell
getdub.exe verify --volume D:\ --expect-files-min 100 --integrity
```
*Проверяет целостность БД (`PRAGMA integrity_check`) и сверяет фактические данные с ожидаемыми. Возвращает код ошибки (0 = OK, >0 = провал проверки), что удобно для скриптов.*

## ⚙️ Как это работает "под капотом" (Алгоритм "Воронка")

Чтобы не хешировать терабайты данных зря, `getdub` использует многоуровневую фильтрацию:
1. **Сбор метаданных:** Чтение через MFT (быстро) или `walkdir` (универсально). Группировка файлов по **размеру**. Файлы с уникальным размером сразу отбрасываются.
2. **Частичный хеш (Partial Hash):** Для файлов с одинаковым размером вычисляется xxHash3 от первых 4 КБ. Если хеши не совпадают, файлы отбрасываются.
3. **Полный хеш (Full Hash):** Только для файлов, прошедших первые два этапа, вычисляется криптографический хеш BLAKE3 всего файла.
4. **Результат:** Файлы с одинаковым полным хешем гарантированно являются дубликатами.

*Примечание:* Если прямой доступ к MFT/USN блокируется ОС (например, из-за BitLocker или политик безопасности), `getdub` автоматически и бесшовно переключается на стандартный обход файловой системы (`walkdir`), о чем сообщает предупреждением `WARN` в логе. Это штатный режим работы.

## 💡 Типовые сценарии использования

### Сценарий А: Очистка медиатеки от дубликатов
1. `getdub idx drive D --include "*.mp3,*.flac,*.wav" --hash`
2. `getdub fdb query --duplicates > dups.txt`
3. Открываете `dups.txt`, выбираете, какие копии удалить вручную.

### Сценарий Б: Ежедневное обслуживание системного диска
1. Утром запускаете: `getdub idx drive C --incremental --hash`
   *(Займет секунды, так как проверит только новые/измененные файлы через USN Journal)*
2. Проверяете статистику: `getdub fdb stats`

### Сценарий В: Анализ перед покупкой нового диска
1. `getdub idx drive D --hash`
2. `getdub fdb export --out analysis.csv`
3. Открываете `analysis.csv` в Excel, сортируете по столбцу `size`, чтобы найти самые большие файлы и потенциальные дубликаты.

## 🧹 Обслуживание и сброс

Если вы хотите начать сканирование "с чистого листа" (например, после смены логики фильтрации):
1. Закройте `getdub`.
2. Удалите папку `fdb` в директории программы (или файл `getdub.fdb`).
3. Запустите индексацию заново.
